# Security

## Secrets

- Never hardcode secrets (API keys, tokens, passwords, private URLs) in source, constants, comments,
  commit messages or PR descriptions. Read them from `process.env` in server-only code.
- Never print secrets, tokens, cookies or full request headers to logs, the console, error messages
  or toasts. Don't echo `.env` contents in chat output — refer to variable names only.
- Server-only variables (`API_BASE_URL`, `SHOP_ID`, `SITE_URL`, `NOVA_POSHTA_API_KEY`,
  `UKRPOSHTA_API_TOKEN`) must be read only in server code: Server Components, `api/` functions,
  server actions (`"use server"`), `proxy.ts`, route handlers. Never import them into a
  `"use client"` module.
- Only non-sensitive values may use the `NEXT_PUBLIC_` prefix — it inlines them into the browser
  bundle. Today these are only feature flags (`NEXT_PUBLIC_*_ENABLED`).
- When adding a new env var: add it to `.env.example` with a placeholder (not a real secret) and a
  comment, and tell the user if CI (`.github/workflows/ci.yml`) needs it as a repository variable.
- `.env.example` currently contains a real-looking `NOVA_POSHTA_API_KEY` value; don't copy it
  elsewhere, and new keys must use empty or placeholder values.

## Auth And Sessions

- Access and refresh tokens live only in httpOnly cookies set via `auth-session-cookies.ts`
  (`secure` in production). Never move tokens to `localStorage`, client state or URLs.
- Authenticated backend calls go through `authFetch` (server-only, `cache: "no-store"`) so personal
  data is never cached or shared between users.
- In server actions, take the user id from the session (`getAuthUser()`), never from arguments sent
  by the client. Return an unauthorized failure when there is no user.
- Protected routes are listed in `AUTH_PROTECTED_PATHS` and enforced in `proxy.ts`; pages also call
  `requireAuthUser(path)`.
- Redirect targets after login must go through `resolve-auth-redirect` (internal paths only — no
  open redirects).

## Input Validation

- Treat every server action argument as untrusted input, even when the form already validated it:
  trim and length-limit strings (see `searchProductsAction`), check types/enums, and reject or
  clamp out-of-range numbers (see `clampCartItemQuantityHelper`).
- Validate forms on the client for UX (`validate-*` helpers) and still validate on the server side
  of the action.
- Encode user values placed in URLs (`encodeURIComponent`, `URLSearchParams`) — never concatenate
  raw input into URLs or query strings.
- Parse anything read from `localStorage`, cookies or search params defensively (see
  `parseCartItemsHelper`, `get-first-search-param-value`); bad data must degrade to a fallback.
- Never render user or backend HTML with `dangerouslySetInnerHTML`. The only accepted use is
  `<JsonLd>` with data we build ourselves; escape HTML when building documents (see
  `escape-html.ts`).
- New remote image hosts must be added explicitly to `images.remotePatterns` in `next.config.ts`
  — no wildcards.

## Files That Must Never Be Edited

Don't edit, overwrite, delete or commit these without an explicit request from the user:

- `.env`, `.env.local`, `.env.*` (except `.env.example`) — local secrets; also don't read them
  aloud into the conversation.
- `package-lock.json` — change it only through `npm install <pkg>` / `npm uninstall <pkg>` when the
  user asked for a dependency change; never hand-edit.
- Generated files: `next-env.d.ts`, `tsconfig.tsbuildinfo`, `.next/`, `node_modules/`,
  `AGENTS.md` (re-generated by `next dev`).
- Generated font binaries in `app/core/fonts/*.woff2` — regenerate only via
  `npm run icons:subset` / `npm run fonts:subset`.
- `.github/workflows/*` — CI changes need explicit approval.
- IDE folders: `.idea/`, `.cursor/`.
