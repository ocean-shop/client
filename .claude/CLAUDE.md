# Ocean Shop — Storefront Client

Customer-facing storefront for Ocean Shop: home page, catalog with filters and search, product pages,
cart, checkout (Nova Poshta / Ukrposhta delivery), OTP login, and a user cabinet (profile, addresses,
orders, favorites) plus static info pages. The UI is in Ukrainian (`<html lang="uk">`, prices in ₴).
All data comes from the separate Ocean Shop backend at `API_BASE_URL`, scoped to one shop by `SHOP_ID`.

Stack: Next.js 16 (App Router, React Compiler, `proxy.ts`), React 19, TypeScript (strict),
Tailwind CSS 4, TanStack Query 5. No test runner is set up.

Detailed rules live in `.claude/rules/` and are loaded automatically:

- `rules/architecture.md` — folder layout, nested components, data flow, state
- `rules/code-style.md` — naming, formatting, imports, preferred patterns and anti-patterns
- `rules/security.md` — secrets, env vars, input validation, files never to edit
- `rules/git-workflow.md` — branches, commits, PRs (only when working with git)

## Next.js Version Warning

This is NOT the Next.js you know. This version has breaking changes — APIs, conventions and file
structure may differ from default assumptions (e.g. `middleware.ts` is now `proxy.ts`, route props are
typed with the global `PageProps<"/route">` / `LayoutProps<"/">` helpers, `params` / `searchParams`
are Promises). Read the relevant guide in `node_modules/next/dist/docs/` before using an unfamiliar
API, and heed deprecation notices. `AGENTS.md` carries the same warning and is re-generated by
`next dev` — leave it as is.

## Setup And Commands

Requirements: Node.js 22 (same as CI), npm (lockfile is `package-lock.json`).

```bash
npm ci                    # install exact dependencies from the lockfile
cp .env.example .env      # then fill in values; see rules/security.md

npm run dev               # dev server on http://localhost:3002
npm run build             # production build (also type-checks and prerenders pages)
npm run start             # serve the production build (run `build` first)

npm run lint              # ESLint (next core-web-vitals + typescript configs)
npm run format            # Prettier — write
npm run format:check      # Prettier — check only
npm run check             # lint + format:check + build — exactly what CI runs

npm run icons:subset      # rebuild the Material Symbols font after using a new icon name
npm run fonts:subset      # rebuild the Inter / Unbounded font subsets
```

There is no `test` script. Don't add or write unit tests unless asked; verify changes with
`npm run check` and by exercising the running app.

`npm run build` needs a reachable `API_BASE_URL` and a `SHOP_ID` — without them prerendering hangs
on page fetches.

## Code Conventions That Differ From Defaults

Short list; full detail in `rules/code-style.md` and `rules/architecture.md`.

- One component per folder: `name/name.tsx` + `name/types/name.types.ts` +
  `name/constants/name.constants.ts`; local children go under `name/components/` (recursively).
- No inline types or static values in components — they go to `types/` and `constants/` files,
  including Tailwind class strings (`*_CLASS_NAME` constants) and all UI copy.
- Arrow functions only (`export const X = () => {}`); named exports everywhere except Next route
  files (`page`, `layout`, `loading`, `not-found`, `sitemap`, `robots`, `manifest`), which
  `export default`.
- Suffixes: helper functions end in `Helper` (`buildProductHrefHelper`), server actions end in
  `Action` (`searchProductsAction`), hooks start with `use`.
- `type` aliases, never `interface`; `import type` for type-only imports.
- Colors only from the `@theme inline` tokens in `app/globals.css` (`bg-accent`, `text-muted`, ...).
- Prettier: double quotes, semicolons, `printWidth: 100`, `trailingComma: "es5"`.

## Architecture Notes

- Everything lives in `app/` (no `src/`). The `@/*` alias maps to the repo root, so imports read
  `@/app/...`.
- `app/(pages)/` — route groups and feature pages; `app/layouts/` — header, footer, cart modal,
  bottom tab bar; `app/components/` — home-page and cross-page feature components; `app/ui/` —
  presentational shared UI; `app/shared/` — domain modules (auth, cart, products, favorites,
  delivery, orders, seo, ...); `app/core/` — infrastructure (api, providers, hooks, stores, fonts).
- Server Components fetch through `api/` functions; client code reaches the backend only through
  server actions (`actions/`), because `API_BASE_URL` is server-only.
- Auth tokens live in httpOnly cookies; `proxy.ts` refreshes them before render.
- Client state (cart, favorites, toasts) is module-level stores read via `useSyncExternalStore`.

## Workflow Rules

Before saying a change is done, run what CI runs (`.github/workflows/ci.yml`, triggered on every
push and PR):

```bash
npm ci            # only if dependencies changed
npm run check     # lint → format:check → build
```

- Fix lint and type errors instead of disabling rules or adding `@ts-ignore` / `eslint-disable`.
- If `format:check` fails, run `npm run format` and re-check.
- If a new Material Symbols icon name was used, run `npm run icons:subset` and include the updated
  font file.
- Before adding or changing a backend call, check the backend's OpenAPI spec at
  `${API_BASE_URL}/docs-json` to confirm the route, params and response shape.
